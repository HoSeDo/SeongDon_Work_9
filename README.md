# 🎮 언리얼 엔진 5 숫자 야구 멀티플레이 게임 (HSDChatX)

언리얼 엔진 5(UE5)를 사용하여 구현한 **실시간 멀티플레이 숫자 야구(Bulls and Cows) 및 인게임 대화 시스템** 프로젝트입니다. 
서버-클라이언트 구조(RPC)를 활용한 게임 데이터 동기화와, 유저가 게임 기록을 실시간으로 확인하고 복기할 수 있는 **스크롤 기반 인게임 로그 누적 시스템** 구현 과정을 정리한 문서입니다.

---

## 📌 프로젝트 개요
기존의 개발자 디버깅용 화면 로그(`GEngine->AddOnScreenDebugMessage`)는 배포(Shipping) 빌드 시 완전히 삭제되어 유저가 게임 기록을 볼 수 없고, 짧은 시간 내에 사라져 게임 진행 상황을 복기하기 어렵다는 치명적인 문제가 있었습니다. 

본 프로젝트에서는 이를 해결하기 위해 **UMG(Unreal Motion Framework)**와 **C++ 및 블루프린트 연동**을 통해 배포 버전에서도 영구적으로 작동하며 마우스 휠 스크롤이 가능한 **진짜 인게임 채팅/로그 시스템**을 구축했습니다.

---

## 🛠️ 핵심 구현 메커니즘 & 아키텍처

### 1. 전체 데이터 흐름 (네트워크 아키텍처)
1. **서버(Server):** 플레이어의 투구 입력(3자리 숫자)을 받아 스트라이크(S) / 볼(B) 판정 및 게임 진행 상태(남은 시간, 현재 턴)를 계산합니다.
2. **클라이언트 RPC(ClientRPC):** 판정된 문자열 결괏값(예: `플레이어1(1/3): 123 -> 1S1B`)을 로컬 플레이어 컨트롤러(`AHSDPlayerController`)로 안전하게 전송합니다.
3. **UI 이벤트 바인딩:** 플레이어 컨트롤러가 로컬 클라이언트의 UI 위젯 함수(`AddChatLog`)를 호출하여 화면에 데이터를 밀어넣습니다.

---

## 🧱 주요 컴포넌트 및 UI 구조

### 1. 메인 알림 패널 (`WBP_HSDNotificationText`)
* **턴 상태 표시:** 현재 차례인 플레이어와 제한 시간 타이머(`TurnTimer`)를 화면에 실시간으로 노출합니다.
* **Canvas Panel Slot 설정:** `Size To Content`를 활용하여 텍스트의 길이에 맞게 레이아웃이 유연하게 늘어나도록 배치 구조를 최적화했습니다.

### 2. 채팅 및 로그 위젯 (`WBP_HSDChatInput`)
* **로그 저장 창고 (`SB_ChatLog`):** 디자이너 화면에서 `Scroll Box` 컴포넌트를 배치하고, 블루프린트에서 제어할 수 있도록 `Is Variable` 속성을 활성화했습니다. 내용이 많아지면 자동으로 마우스 휠 스크롤바가 활성화됩니다.
* **동적 위젯 생성 시스템:** 메모리 관리와 확장성을 위해, 새 로그가 들어올 때마다 통째로 텍스트를 갈아엎는 방식이 아닌 **독립된 한 줄짜리 위젯을 생성하여 스크롤 박스의 자식(Child)으로 계속 누적**시키는 방식을 채택했습니다.

### 3. 개별 로그 라인 위젯 (`WBP_ChatLine`)
* `Create Widget` 노드는 언리얼 순정 Text Block을 직접 생성할 수 없으므로, 한 줄의 텍스트 레이아웃을 담당하는 전용 가벼운 위젯(`WBP_ChatLine`)을 별도로 설계했습니다.
* **구조:** 내부에는 변수 처리된 `Text Block` 하나만 존재하며, 외부에서 텍스트를 주입받는 `SetLogText` 커스텀 함수를 포함합니다.

## 🚀 블루프린트 스크립팅 상세 (구현 핵심)

### 🔹 `WBP_HSDChatInput` 이벤트 그래프 조립 흐름
C++ ClientRPC 또는 로컬 이벤트로부터 새로운 문자열(`In Message`)이 수신되면 다음 순서로 노드가 실행됩니다:

```
[Custom Event: AddChatLog] 
        ⬇️
[Create Widget] ──(Class: WBP_ChatLine 선택)
        ⬇️
[SetLogText] ─────(Create Widget의 Return Value 타겟 / In Message 데이터 전달)
        ⬇️
[Add Child] ──────(Target: SB_ChatLog / Content: 생성된 WBP_ChatLine 위젯)
        ⬇️
[Scroll to End] ──(Target: SB_ChatLog / 새로운 로그가 추가되면 최신 위치로 스크롤 강제 이동)
```

1. **`Create Widget` 노드 사용:** 드롭다운 목록에서 동적으로 생성할 타겟 클래스를 `WBP_ChatLine`으로 지정합니다.
2. **`SetLogText` 호출:** 생성된 위젯 객체(파란색 리턴 핀)를 타겟으로 잡고, 이벤트 인풋인 분홍색 `In Message` 문자열을 넘겨주어 텍스트 블록의 글자를 세팅합니다.
3. **`Add Child` 노드 연동:** 변수로 선언해 둔 스크롤 박스(`SB_ChatLog`)를 가져와 `Target`에 꽂고, 방금 글자가 세팅된 위젯을 `Content`로 추가합니다.
4. **`Scroll to End` 디테일 처리:** 새 대화나 판정 결과가 밑에 쌓여 화면 밖으로 넘어갈 때, 스크롤바를 자동으로 맨 아래로 밀어주어 유저가 항상 최신 피드백을 확인할 수 있도록 마감했습니다.

---

## 🎯 구현 결과 및 기대 효과
* **암기 게임 탈피:** 유저가 이전 턴에 입력했던 숫자들과 스트라이크/볼 결과를 마우스 스크롤을 통해 언제든지 위아래로 확인하며 영리하게 추리할 수 있게 되었습니다.
* **완벽한 패키징 대응:** 개발자용 임시 화면 로그(`AddOnScreenDebugMessage`)와 달리 배포(Shipping) 빌드에서도 UI 프레임워크 위에서 영구적이고 안정적으로 구동됩니다.
* **디자인 확장성 확보:** 대화 기록 라인이 독립된 위젯(`WBP_ChatLine`)으로 분리되어 있어, 향후 일반 채팅(흰색), 알림 메시지(노란색), 에러 메시지(빨간색) 등 로그 종류에 따른 스타일 및 폰트 커스터마이징이 매우 용이합니다.
